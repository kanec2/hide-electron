# Known Limitations & Architectural Decisions

## 1. Рассинхронизация ProjectTree при внешних изменениях
**Статус:** Известное ограничение  
**ADR:** [Asset Sync Strategy](https://github.com/kanec2/hide-electron/issues/XXX)

### Проблема
`ProjectPanel` не подписан на события Chokidar напрямую. При изменении файлов вне IDE (через проводник ОС):
- ✅ `AssetBrowser` обновляется корректно (через `onAssetsChanged` → IPC).
- ❌ `ProjectTree` остается устаревшим до следующего ручного обновления (F5 или переоткрытие папки).

### Обоснование
Прямая подписка дерева на Chokidar требует сложного маппинга путей и может вызывать проблемы производительности при массовых изменениях (например, `git checkout`). Текущая стратегия разделяет "тяжелое" дерево и "легкий" браузер ассетов.

### Workaround
Для принудительного обновления дерева используйте контекстное меню → "Refresh" или перезагрузите проект.

## 2. Синхронные FS-операции в Main Process
В `FileSystemHandlers` используются `readdirSync`, `renameSync`, `rmSync`.
- **Риск:** Блокировка Event Loop при работе с огромными директориями.
- **План:** Миграция на `fs.promises` или Worker Threads для тяжелых операций в будущих версиях.

## 3. LSP через stdin/stdout
Haxe Language Server работает через pipe, а не TCP.
- **Плюс:** Нет накладных расходов на сеть, проще отладка.
- **Минус:** Сложнее масштабировать на несколько воркспейсов одновременно.
