# Архитектура HIDE on Electron

## Обзор слоев
Приложение построено по принципам чистой архитектуры с четким разделением ответственности между процессами Electron.

### Main Process (`electron_main`)
Отвечает за взаимодействие с операционной системой, файловой системой и управлением окнами.
- **ElectronMain.hx**: Точка входа. Инициализирует ServiceLocator и запускает AutoWindow.
- **AutoWindow.hx**: Управляет жизненным циклом окна, регистрирует IPC-обработчики (`ipcMain.handle`) и настраивает меню.
- **FileSystemHandlers.hx**: Централизованный фасад для всех операций с файловой системой. Изолирует логику FS от UI.

### Renderer Process (`electron`)
Отвечает за пользовательский интерфейс и бизнес-логику IDE.
- **hide/core/Ide.hx**: Корневой компонент приложения.
- **hide/electron/ElectronBackend.hx**: Реализация `IIdeBackend`, связывающая доменную логику с IPC через `IpcBridge`.
- **hide/infrastructure/ipc/IpcBridge.hx**: Типизированный клиент для безопасных вызовов Main процесса (`invokeSafe`).

## Ключевые принципы
1. **Безопасность IPC**: Renderer никогда не имеет прямого доступа к `fs` или `child_process`. Все операции проходят через строго типизированные каналы.
2. **Ленивая загрузка**: Дерево проекта не загружается целиком. Используется флаг `isLoaded` в `ArboristNode` для подгрузки детей по требованию.
3. **Двойная синхронизация ассетов**: 
   - *Активная*: Прямой вызов pipeline при действиях пользователя.
   - *Пассивная*: Реакция на события Chokidar для внешних изменений.
